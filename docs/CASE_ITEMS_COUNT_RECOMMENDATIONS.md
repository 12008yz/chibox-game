Проверь всё за собой ещё раз. Что бы не было ошибок или несостыковок в логике.

Предупреждения по плану A–E
A — Веса и RTP (экономика)
Высокий RTP на проде — часто из-за наполнения кейса, а не только формулы весов. Пример: «Стандартный» ~104% RTP при щедром пуле.
Мало предметов (16 и меньше) — слабая рулетка и странный RTP (Космический, Ледяной, Санитарный).
Синтетический отчёт (--synthetic) не отражает реальную витрину — ориентир только на case:rtp-report:prod.
Пороги в отчёте: RTP >85% — риск маржи; <55% — слишком жёстко; «катастрофа» >25%; <8 предметов — предупреждение.
B — Near-miss (только визуал)
Результат с сервера не меняется — соседние слоты могут показывать дорогие предметы «для эффекта».
Отключается: VITE*ROULETTE_NEAR_MISS=false или prefers-reduced-motion.
На мобилке near-miss и звуки завязаны на getCasePrice — после правки берётся caseData.price, но превью daily/status по-прежнему может подставлять цену из statusData.
C — Soft-pity
По умолчанию выключено (DROP_SOFT_PITY_ENABLED=false).
Серия считается на пользователя по всем платным открытиям, не по конкретному кейсу.
Без Redis на нескольких инстансах pity расходится (in-memory только на одном процессе).
Порог «хорошего» дропа = 85% цены кейса — совпадает с tier good на фронте, но это разные системы.
D — Provably fair
По умолчанию выключено; нужна миграция (user_fair_seeds, cases.pf*\*).
Полная проверка только после раскрытия server seed (POST /rotate).
Смена правил весов / наполнения ломает replay старых открытий.
Verify учитывает два пути (прямое / инвентарь) — после фикса они согласованы, но логика дубликатов всё ещё разная при бонусах.
E — Live feed и звуки
Разные пороги у ленты и у звуков при открытии (см. таблицы в доке) — это не баг, но визуально может казаться несогласованным.
Tier high на фронте (цена ≥100₽) может подсветить карточку, даже если бэкенд не поставил is_rare_item.
Звуки только при открытии кейса, не в глобальной ленте (иначе шум).
Бесплатные кейсы: is_rare по абсолютной цене ≥100₽ только если у шаблона нет цены кейса.
Общее (вне пунктов плана, но важно)
Превью шансов: для кейса из инвентаря с подпиской — GET /case-templates/:id/items?source=subscription, иначе бонус в превью может не совпасть с реальным дропом.
Контент кейсов (CASE_ITEMS_COUNT_RECOMMENDATIONS.md) — отдельная задача: добить наполнение проблемных шаблонов на проде.
